# Nixvim Dendritic Rewrite — Fix base.nix

## Current state
`flake.nix`, all module files, and all lua files are already written and in place.
`nix flake check --impure` evaluates fully but fails at Lua build with a stylua formatting error in the generated init.lua (line 267 — likely the autoCmd `__raw` callbacks).

The structural problem in `base.nix`: harpoon/oil/undotree keymaps are `++ []` appended to the non-plugin keymaps list. The nixvim module system merges `keymaps` lists from multiple top-level `keymaps = [...]` declarations across imported modules automatically. Since everything is in one file here, the fix is to split `base.nix` into separate files — one per plugin — exactly mirroring the original `config/plugins/` structure, but each wrapped in `flake.modules.nixvim.base`.

## Wrong approach (what was done)
Single `base.nix` with all plugins merged into one attrset, forcing manual `++` to combine keymaps.

## Right approach
Split `base.nix` into multiple files under `modules/base/`, each a flake-parts module that sets `flake.modules.nixvim.base`. The nixvim module system merges them. Each file is a faithful copy of the original plugin file, wrapped in `flake.modules.nixvim.base = { ... }: { ... }`.

## New structure for modules/base/

```
modules/base/
  default.nix      # opts, globals, autoCmd, files, extraPackages, withPython3, viAlias etc. + extraPlugins + extraFiles
  keymaps.nix      # non-plugin keymaps (copy of config/keymaps.nix)
  harpoon.nix      # copy of config/plugins/harpoon.nix
  mini.nix         # copy of config/plugins/mini.nix
  oil.nix          # copy of config/plugins/oil.nix
  telescope.nix    # copy of config/plugins/telescope.nix
  treesitter.nix   # copy of config/plugins/treesitter.nix
  undotree.nix     # copy of config/plugins/undotree.nix
  plugins.nix      # inline plugin enables: comment, fidget, fzf-lua, markdown-preview, nvim-autopairs, nvim-surround, which-key
```

Each file looks like:
```nix
{ ... }:
{
  flake.modules.nixvim.base = { pkgs, ... }: {
    # content from original file
  };
}
```

The nixvim module system merges all `flake.modules.nixvim.base` values because it's a `deferredModule` — multiple files can set the same key and their contents merge exactly like NixOS modules.

## Steps

1. Delete `modules/base.nix`
2. Create `modules/base/` directory with the files listed above
3. Move `modules/_lua/` reference in `default.nix` to `modules/base/_lua` symlink or adjust path to `../_lua/`
4. Run `git add -A && nix flake check --impure`
5. If passes, delete `config/`

## lua path note
`modules/base/default.nix` will reference `../_lua/colorschemes.lua` etc. (one level up from `modules/base/` to `modules/_lua/`).
